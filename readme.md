# Балансировщик для отказоустойчивого WordPress

WordPress предусматривает горизонтальное масштабирование - при использовании внешних хранилищ для файлов и внешних БД можно запустить несколько инстансов WordPress, но перед ними нужен балансировщик. Итого получается два каскада из серверов Angie:
1. front - фильтрует трафик и обеспечивает распределение трафика на хосты с динамичным и статичным контентом
2. back-static - web-сервер со статичным контентом
3. back-dynamic - web-серврер с динамичным содержимым

## front

Обратные прокси с настроенными фильтрами и ограничениями для непосредственного подключения пользователей.

## back-static

Простой web-сервер со статичным содержимым WordPress. Статичное содержимое формируется движком WordPress хостов `back-dynamic` в общем отказоустойчивом/распределённом хранилище, а хосты `back-static` его только читают.

## back-dynamic

Хосты с Angie в режиме fastCGI-proxy к движку WordPress.

## Демонстрационный стенд

В репозитории размещены файлы конфигурации для демонстрации средствами docker compose отказоустойчивой конфигурации wordpress в части web-серверов.
На хостовой системе должен быть установлен `fail2ban`, и добавлены конфигурационные файлы из каталога `etc`.
Должен быть установлен `certbot` для получения Let's encrypt.

## Реализованные на демостенде функциональные возможности:
1. Ограничение нагрузки - 1 запрос в секунду к динамичному содержимому
2. `fail2ban` на час после десяти фактов нарушения ограничения нагрузки
3. https
4. поддержка http/2 и http/3
5. редирект с http на https
6. hsts на час
7. доступ в "админку" WordPress по белым спискам
8. кэширование контента
9. компрессия контента
10. упрощённый cdn с отказоустойчивостью - статичный контент отдаётся с нескольких отдельных серверов
11. горизонтальное масштабирование "cdn" - новые сервреры не требуют особой настройки - просто запускается ещё один экземпляр, его адрес нудно добавить в `front-1.conf`
12. отказоустойчивость движка wordpress - wordpress запускается в режиме active-passive. При выходе из строя активной ноды wordpress трафик переключается на горячий резерв

## Возможности доступные при развёртывании на распределённой инфраструктуре
1. `front` так же можно горизонтально масштабировать, добавляя адреса сервреров в DNS rount robin
2. развернув для WordPress отказоустойчивые БД можно так же горизонтально масштабировать движок WordPress и получить _fault tolerance_ вместо реализованной _high availability_
